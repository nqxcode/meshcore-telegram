# Мост MeshCore ↔ Telegram

Heltec V4.3 переведён на MeshCore USB Companion `v1.18.0-81dbae5`.
Точка входа нового моста — `meshcore_bridge.py`; прежний `bridge.py` сохраняет общую обработку Telegram и возможность запуска с Meshtastic после восстановления прошивки.

## Радионастройки и каналы

Радионастройки Тулы:

| Параметр | Значение |
| --- | --- |
| Частота | 868,731 МГц |
| BW | 62,5 кГц |
| SF | 8 |
| CR | 7 |
| Хэш маршрута | 2 байта |

По умолчанию канал моста — **#tulameshbridge**, индекс 1. Можно переключить мост на **Public**, индекс 0. В обе стороны пересылается только выбранный канал. Личные сообщения MeshCore в Telegram не пересылаются.

На Android нужен отдельный узел с MeshCore Companion BLE и приложение MeshCore: задайте те же радиопараметры и добавьте канал по имени `#tulameshbridge`. Это канал с ключом, вычисляемым из имени, а не секретная группа.

## Настройка и запуск

### Файл окружения

Зависимости нового моста установлены в `.meshcore-venv`; версии записаны в `requirements-meshcore.txt`.
Пример настроек — [`bridge.env.example`](bridge.env.example). При первом запуске
скопируйте его в `bridge.env` и ограничьте доступ:

```sh
cp -n bridge.env.example bridge.env
chmod 600 bridge.env
```

Укажите в `bridge.env` токен от @BotFather, ID Telegram-группы и USB-порт узла.
Файл `bridge.env` исключён из Git.

### Ручной запуск

Для ручного запуска из каталога проекта загрузите переменные в окружение:

```sh
set -a
. ./bridge.env
set +a
.meshcore-venv/bin/python meshcore_bridge.py
```

### Запуск через systemd

При использовании systemd файл должен быть подключён через `EnvironmentFile=`
в основном unit. Значения `MESHCORE_CHANNEL` и `MESHCORE_CHANNEL_NAME` также
заданы в `meshcore-systemd.conf`; при настройке другого канала обновите их там.

Для переключения существующего системного сервиса выполните из каталога проекта:

```sh
sudo bash ./install_meshcore_service.sh
```

Установщик подставляет фактический каталог проекта вместо `@PROJECT_DIR@` в шаблоне
`meshcore-systemd.conf`. После переноса проекта запустите установщик повторно;
проверьте также пути в `EnvironmentFile=` и других настройках основного unit.

Имя сервиса остаётся `meshtastic-telegram`, токен, группа и файл состояния сохраняются из `bridge.env`. Drop-in задаёт новый исполняемый файл и канал. При потере USB процесс завершается, а systemd перезапускает его. Проверка канала и ключа при запуске предотвращает отправку в неверную группу.

### Резервные копии и откат

Копии исходной flash (16 МБ), настроек и systemd-unit находятся в `migration/`.

> Эти файлы содержат ключи устройства; каталог доступен только владельцу.

Для отката:

1. Остановите сервис.
2. Восстановите полный образ Meshtastic через esptool по адресу `0x0`.
3. Удалите только drop-in `meshcore.conf`.
4. Выполните `systemctl daemon-reload`.
5. Запустите сервис.

## Работа с Telegram

### Пересылка сообщений и ответы

Все обычные текстовые сообщения участников настроенного `TELEGRAM_CHAT_ID` пересылаются в LoRa. Сообщения ботов и сообщения из других групп игнорируются. В личке доступны только `/status` и `/nodes`; ответ приходит только в личку, без публикации в группе. Вложения без текста не пересылаются.

Ответы на сообщения и команды группы отправляются в личку автору. Исключение — `/status` и `/nodes`: ответы приходят только в чат вызова — в группу или личку. Для получения остальных личных ответов каждый участник должен открыть личный чат с ботом и нажать «Старт»; если личка недоступна, ответ в группу не дублируется. Сообщения из MeshCore по-прежнему поступают в группу. Для анонимных отправителей личный ответ невозможен.

### Команды бота

- `/channels` или `/channel` — показать текущий канал и команды переключения.
- `/channel public` — переключить всю Telegram-группу на общий радиоэфир Public.
- `/channel bridge` или `/channel #tulameshbridge` — вернуться в отдельный канал.
- `/status` — состояние подключения MeshCore USB, канал, время работы моста и число известных контактов. Соединение с устройством не означает доступность всей радиосети.
- `/nodes` — список известных узлов по имени, до 10 записей в сообщении, с полными ID и короткими именами на отдельных строках. Наличие узла в списке не означает, что он сейчас в сети.
- `/send текст` — дополнительный способ отправки в настроенный LoRa-канал. Поддерживается `/send@имя_бота текст`. Команды `/status` и `/nodes` обрабатываются локально; команды, адресованные другим ботам, игнорируются.

### Переключение канала

Переключать канал может любой участник настроенной Telegram-группы. Выбор общий для группы, сохраняется в файле состояния и восстанавливается после перезапуска. Поддерживается адресация `/channel@имя_бота public`. При переключении очередь прежнего канала очищается; новые сообщения Telegram идут в выбранный канал. Ответы из радио помечаются названием канала. Лимит частоты и защита от повторов остаются общими для двух каналов.

## Дополнительные настройки

| Переменная | Описание |
| --- | --- |
| `MESH_SEND_INTERVAL=1` | Минимальный интервал между попытками отправки в радио, в секундах. |
| `BRIDGE_STATE_FILE=/путь/bridge-state.json` | Файл состояния; по умолчанию рядом с `bridge.py`. Каталог должен существовать и быть доступен для записи. |

Переменные из `bridge.env` должны быть переданы в окружение процесса существующим способом запуска. После изменения настроек перезапустите мост.

## Ограничения и надёжность

### Отправка в радио

Одинаковый текст можно отправлять повторно через 1 секунду; общий интервал между попытками отправки по умолчанию также составляет 1 секунду. Лимит сообщения MeshCore — 120 байт UTF-8 вместе с префиксом `[TG имя]`, с запасом для имени шлюза в радиопакете. Успешный вызов отправки означает передачу устройству, а не подтверждённую доставку получателям.

### Сохранение состояния

Offset Telegram, время попытки отправки и хеши недавних текстов сохраняются до отправки в радио. Это предотвращает повтор после ошибки ответа Telegram или перезапуска. При аварии между сохранением и отправкой команда может быть потеряна; автоматического повтора нет. При первом запуске без файла состояния старая очередь Telegram пропускается. Используйте один процесс моста на бота и файл состояния.

### Входящие сообщения MeshCore

Повторные входящие сообщения MeshCore отсекаются по времени отправителя и тексту в течение 5 минут в памяти процесса (до 4096 записей). Собственные отражённые сообщения не пересылаются обратно в Telegram. После перезапуска этот кэш сбрасывается. Очередь входящих сообщений ограничена 200 элементами; при переполнении новые сообщения отбрасываются с записью в журнал.

## Проверки

Проверки без подключения к Telegram и радио:

```sh
.meshcore-venv/bin/python -m unittest -v test_bridge test_meshcore_bridge test_runtime
```

Для измерения покрытия установите дополнительные зависимости разработки в то же
окружение:

```sh
.meshcore-venv/bin/python -m pip install -r requirements-dev.txt
mkdir -p target/coverage/python
.meshcore-venv/bin/python -m coverage run --source=bridge,meshcore_bridge,configure_meshcore -m unittest test_bridge test_meshcore_bridge test_runtime
.meshcore-venv/bin/python -m coverage report -m
.meshcore-venv/bin/python -m coverage lcov -o target/coverage/python/lcov.info
```

Проверки `ub-mode` используют оригинальные инструменты
[crapper](https://github.com/unclebob/crapper),
[dryer](https://github.com/unclebob/dryer) и
[mutator](https://github.com/unclebob/mutator). При локальной установке в
`.ub-tools/venv` команды такие:

```sh
.ub-tools/venv/bin/crapper --use-existing-coverage --threshold 9.99 bridge.py meshcore_bridge.py configure_meshcore.py
.ub-tools/venv/bin/dryer --threshold 0.8 bridge.py meshcore_bridge.py configure_meshcore.py
.ub-tools/venv/bin/mutator --no-coverage --mutate-all --max-workers 2 --test-command '.meshcore-venv/bin/python -m unittest test_bridge test_meshcore_bridge test_runtime' bridge.py meshcore_bridge.py configure_meshcore.py
```

Перед `crapper` нужно заново получить покрытие. `dryer` выводит кандидаты на
дублирование; код завершения 0 сам по себе не означает, что кандидатов нет.
`mutator --no-coverage` проверяет все места мутаций, включая операторы в
продолжениях строк, которые LCOV не всегда выделяет отдельно. Ключ `--mutate-all`
отключает повторное использование результатов прошлых прогонов. Полный прогон
мутаций выполняется в копиях файлов; тесты используют имитации радио и Telegram.

Результаты применения навыка и причины изменений: [UB_MODE_REPORT.md](UB_MODE_REPORT.md).
